# Changelog

## Unreleased

### Install

- Added `.omp-plugin/marketplace.json` so the repo installs as its own OMP marketplace: `omp plugin marketplace add SenCha930511/omp-pstack` then `omp plugin install omp-pstack@omp-pstack`.
- Added `scripts/verify-install.mjs`, a shared discovery validator used by the packed-tarball and marketplace tests. It runs in an isolated home with host XDG, profile, and config overrides removed.
- Added `scripts/test-marketplace.mjs`, which covers local add, install, list, update, force reinstall, the same-name runtime conflict, and the uninstall-then-install migration offline.
- Documented the marketplace tree-cache copy, version-only upgrade comparison, and the one-runtime-package-per-scope rule in `README.md`, `AGENT-INSTALL.md`, and `poteto-help`.
- Child processes now use verbatim Windows arguments only for `.cmd` wrappers, so paths with spaces and multiline `bun -e` scripts stay intact.

### Upstream sync

- Added `upstream.json`, a per-file manifest with `verbatim`, `local`, and `excluded` rules plus a git blob and mode for every upstream `pstack/skills` file.
- Added `scripts/check-upstream.mjs` and `check:upstream` for offline verification; `--cursor-dir` additionally checks the real upstream commit, tree, blob, and mode.
- Rewrote `sync-upstream.mjs` and `sync-ack.mjs` around the manifest. Clean syncs advance the manifest pin and `cursor.lastSyncedSha` together; syncs with manual work stage copied files under `pending` and hold the baseline until ack.
- Removed pi-mimir tracking from the sync config, workflow, scripts, README, and tests while keeping its MIT attribution in `NOTICE.md`.
- Added `.gitattributes` with `* text=auto eol=lf` so byte-level blob checks agree across Windows and POSIX checkouts.
- Excluded-skill changes require an explicit `sync:ack --exclude`, and the sync workflow runs the live commit/tree/blob inventory check.
- Clean syncs drop manifest entries for files deleted upstream and keep a `localOnly` record when the local file remains.

### Poteto Mode paths

- Added `extensions/pstack/install.ts` to resolve the skill file from the loaded package, then a project-scoped plugin link, then the user-scoped link. A fallback must realpath into the same marketplace's cache entry and carry the expected package and skill names.
- Sticky and one-shot reads re-resolve the anchor on every read, so an upgrade in the middle of a session is picked up on the next turn. The skill cache now keys on file, mtime, and size.
- Native command discovery ignores a stale command path and falls back to the local skill prompt.
- Added resolver tests for project-over-user precedence, marketplace mismatch, wrong package or skill names, escaping links, legacy `PI_CONFIG_DIR`, and missing `cwd`.
- Project `.omp` discovery continues above the nearest git root, so an ancestor project install wins over the user link.

### Guides

- Added `docs/guide/` with eleven chapters covering setup, Poteto Mode, understanding, design, build and cleanup, verification, overnight runs, principles, customization, and recipes. The six images keep the upstream MIT attribution.
- Added `docs/skills.md`, generated by `scripts/docs-index.mjs` from skill frontmatter, with computed workflow, principle, and playbook counts.
- Added `docs:check` and `test:docs`; the link checker now covers every Markdown file under `docs/`.
- Updated `NOTICE.md` with the guide and image provenance and corrected the autonomy and `comment-sicko` tool descriptions.

### Install proof

- Added `proofs/install.json`, a bounded install proof with SHA-256 for every packed file plus the generator, verifier, shared validator, and extension load graph.
- Added `proof:install` to regenerate it and `test:proof` to validate the schema, canonical `package.json` hash, inputs, and live discovery without writing.
- `npm run check` now runs the read-only proof check, and release verification checks the proof package version against the tarball.
- Added proof unit tests for changed bytes, missing files, version drift, unknown schema, forged counts, and the `gitHead`/`devDependencies` canonicalization rule.
- The proof inputs include the command-resolution helpers used by the generator and verifier.

## 0.3.3 - 2026-11-27

### Poteto Mode

- One-shot `/poteto-mode <task>` uses the native `/skill:poteto-mode` path when available and falls back to the local skill prompt when it is not.
- `/poteto-mode sticky <task>` enables sticky mode and runs the task immediately.
- Foreign `skill:poteto-mode` commands with a different path no longer capture the local skill.
- Sticky state remains scoped to the session and subagents; one-shot and sticky task paths preserve attached images.

### Upstream sync

- Added `sync:ack --adapt-only` to record a partial port without advancing `lastSyncedSha`.
- The sync report omits unsafe upstream skill names from CLI suggestions, and `sync:ack` rejects names outside `[A-Za-z0-9._-]+`.
- pi-mimir range failures are reported without advancing `lastCheckedSha`; ack guidance waits for manual verification.
- The workflow runs sync scripts from the main checkout, installs the PR branch toolchain after checkout, and handles missing jq or node.
- The sync scans all non-binary text files, skips binary assets, and preserves executable bits.

### Worktree audit

- Session headers are read from title-first and legacy transcripts, with jq, Node, and awk fallbacks.
- Worktree matching is strict per repo and accepts `additionalDirectories` when a session starts outside the worktree.
- PR state is normalized without jq, so open-PR worktrees remain `hold-open-pr` when jq is unavailable.

### Tests and docs

- Added regression coverage for native skill routing, foreign skill paths, sticky tasks, image forwarding, sync ack safety, pi-mimir errors, title-first sessions, and jq-free PR state.
- Updated install and upgrade instructions for 0.3.3.

## 0.3.2 - 2026-11-27

### Setup

- `setup-pstack` now adds itself to `skills.manualSkills` after it writes the routing. The model catalog drops it from the next session, while `/skill:setup-pstack` and `skill://setup-pstack` keep working.
- The install and upgrade commands in `README.md` and `AGENT-INSTALL.md` point at 0.3.2.

### Upstream sync

- The sync computes the `pstack` range from `lastSyncedSha` with `git log <base>..<head> -- pstack` and `git diff --name-status`, instead of walking a path-filtered GitHub API list until it finds the base. A base that never touched `pstack/` no longer reports the full history.
- The upstream clone keeps full history on one branch (`--single-branch`, blobless, sparse), so any recorded base is reachable.
- The sync no longer makes one GitHub API call per commit. It runs one range script and one diff.
- `lastSyncedSha` resets to `9e278fe`, the last upstream commit under `pstack/`.
- A missing or non-ancestor base now fails the workflow with an error that names `lastSyncedSha`, instead of silently reporting the full history.
- When the range is empty, the sync closes an open `[upstream-sync]` issue with the synced SHA.

### Manual porting

- Added `npm run sync:ack -- --cursor <sha> [--pi-mimir <sha>]`. It validates the SHA, updates `lastSyncedSha` and optionally `piMimir.lastCheckedSha`, and preserves the rest of the config.
- Issue-mode reports end with `### After porting` and the exact ack command, including `--pi-mimir` when a pi-mimir commit is present.

### Docs and skills

- The README model routing examples use Claude Opus 5.5, GPT-5.4, and Claude Sonnet 5.5 instead of provider-specific model IDs.
- The `arena` skill judges model families generically and no longer names a provider.
- Added regression tests for the range script, the ack command, and the issue report instruction.
